巡线小车 + 二轴云台打靶 —— 比赛总结

成绩
85 分 / 100 分，第四名（第一 98，第二三 90，第五 80）


项目概述
STM32F103C8T6 巡线小车搭载 K230 视觉模块 + 二轴云台，沿黑线行驶，依次停在三个圆圈节点（直径 30cm），云台自动瞄准靶心并发射激光。巡线结束后回到起点。


技术架构

硬件
- 主控：STM32F103C8T6
- 视觉：K230（CanMV），独立运行
- 驱动：TB6612 双路电机驱动板
- 传感器：八路巡线模块（PA0-PA7）
- 编码器：电机自带霍尔编码器，260 脉冲/转
  左：PB6（TIM4_CH1）、PB7（TIM4_CH2）
  右：PA15（TIM2_CH1 remap）、PB3（TIM2_CH2 remap）
- 云台舵机：X轴 GPIO40（UART1）、Y轴 GPIO44（UART2）
- 激光：GPIO24，3.3V 供电

软件
| 组件   | 文件         | 说明 |
|--------|-------------|------|
| STM32  | main.c      | PID 巡线、编码器停车、PB15 信号 |
| 编码器 | encoder.c/h | TIM2/TIM4 硬件正交解码，32 位累计 |
| 电机   | motor.c/h   | TIM1 PWM，20kHz |
| K230   | k230_fixed.py | cv_lite 矩形检测 + 霍夫圆备用，云台控制，激光打靶 |


达成项

巡线 ✓
PID 控制（Kp=200, Ki=1, Kd=25），BASE_SPEED=600
丢线时按上次方向原地转向找回

编码器停车 ✓
硬件正交解码（TIM2/TIM4 encoder mode），2x 分辨率（520 脉冲/转）
32 位累计防止 16 位溢出
三个节点阈值：15650 / 24870 / 31020
第四个回到起点：73000
每个节点停 8 秒，PB15 输出高电平

云台瞄准 + 激光打靶 ✓（部分）
cv_lite 矩形检测为主，霍夫圆检测备用
透视变换定位靶心，死区 ±25px
对准后自动打靶 3 次（亮 500ms / 灭 200ms）
稳定对准判定（连续 15 帧）防止误触发


未达成 / 遗留问题

STM32 → K230 通信 ✗
最大短板。尝试了 GPIO 电平检测（IO10 + 10kΩ 下拉电阻）和 UART 串口（PB10 USART3 → IO10 UART1 RX），均未成功。

可能原因：
1. K230 IO10 引脚映射不确定（丝印 vs FPIOA 编号）
2. K230D 的 GPIO 输入模式 / PULL_DOWN 支持有限
3. 电平兼容性

影响：K230 无法知道小车是否到站，激光打靶依赖"对准即打"逻辑，缺少到站确认，打靶时机不够稳定。


关键调参记录
- 从定时停车迁移到编码器停车，解决了电池电压影响
- EXTI 中断读编码器 → 硬件 TIM encoder mode（解决 JTAG 引脚冲突、中断可靠性）
- 阈值经历了多轮微调：从原始估算值逐步校准到 15650/24870/31020
- K230 激光从常亮 → 3 脉冲打靶 → 稳定对准判定


经验教训

1. 跨板通信要优先验证
   STM32 和 K230 的通信链路应最早搭建并验证，而不是等项目尾声才处理

2. 编码器是巡线比赛的标配
   定时停车受电池电压影响太大，编码器一次投入终身受益

3. 硬件编码器模式最可靠
   TIM 正交解码零 CPU 开销，比 EXTI 中断稳定得多

4. K230 引脚映射要查原理图
   丝印 "IO10" 不一定等于芯片 FPIOA 编号
